## 1. Objectif unique

Produire un **tableau de passage** : P&L brut → P&L normalisé.

---

## 2. Exigences fonctionnelles

### Couche 1 : Lecture comptable

#### FR-101: Classification des journaux
**Priority:** Must Have

L'outil identifie automatiquement la nature des journaux.

| Code | Nature | Usage |
|------|--------|-------|
| OD, OD*, AN | Opérations diverses | Zone de vigilance |
| SAL, PAI* | Paie | Récurrent, effet congés |
| VTE, FAC* | Ventes | Produits opérationnels |
| ACH, FRN* | Achats | Charges opérationnelles |
| BQ, BNQ* | Banque | Hors P&L |

**Acceptance Criteria:**
- [ ] Détecte les journaux par pattern de code
- [ ] Flagge OD décembre si volume > 3x moyenne mensuelle
- [ ] Affiche la répartition par journal

---

#### FR-102: Classification PCG des comptes
**Priority:** Must Have

L'outil classe chaque compte selon le PCG.

| Classe | Nature | Comportement attendu |
|--------|--------|---------------------|
| 60 | Achats | Récurrent |
| 61-62 | Services | Récurrent/saisonnier |
| 63 | Impôts/taxes | ABT fréquent |
| 64 | Personnel | Récurrent, creux août |
| 67 | Exceptionnel charges | One-shot |
| 68 | Dotations | À décomposer |
| 69 | IS | One-shot annuel |
| 77 | Exceptionnel produits | One-shot |
| 78 | Reprises | À coupler avec 68 |

**Acceptance Criteria:**
- [ ] Chaque compte est classé par nature PCG
- [ ] Le comportement attendu est déterminé
- [ ] Les comptes de provision/reprise sont identifiés

---

#### FR-103: Détection des mécanismes ABT
**Priority:** Must Have

L'outil détecte automatiquement les comptes d'abonnement (488) qui soldent à zéro.

**Pattern ABT:**
```
Janv-Nov : provisions mensuelles régulières
Décembre : contrepassation + charge réelle
Solde exercice : ~0 (tolérance 1%)
```

**Acceptance Criteria:**
- [ ] Identifie tous les comptes 488xxx
- [ ] Calcule le solde annuel de chaque compte 488
- [ ] Flagge comme ABT si solde < 1% du mouvement total
- [ ] Liste les ABT avec leur objet (CFE, prud'hommes, etc.)

---

#### FR-104: Séparation amortissements vs provisions
**Priority:** Must Have

L'outil distingue les dotations récurrentes des provisions ponctuelles.

| Type | Comptes | Traitement |
|------|---------|------------|
| Amortissements | 681 | Aucun (récurrent) |
| Dépréciations | 6816, 6817 | Analyser |
| Provisions risques | 6815, 687 | Analyser le motif |
| Reprises | 781, 787 | Coupler avec dotation |

**Acceptance Criteria:**
- [ ] Les 681 récurrents ne sont pas retraités
- [ ] Les 6815/687 sont analysés individuellement
- [ ] Chaque provision est couplée avec sa reprise éventuelle

---

### Couche 2 : Tableau de passage

#### FR-201: Calcul du tableau de passage mensuel
**Priority:** Must Have

Pour chaque mois, l'outil produit un tableau de passage.

```
Résultat brut du mois         XXX €
───────────────────────────────────
RETRAITEMENTS
(-) IS (quote-part mensuelle) -XX €
(-) Provisions net            -XX €
(+) Contrepassation ABT       +XX €
(-) Exceptionnel net          -XX €
───────────────────────────────────
= Résultat normalisé          XXX €
```

**Acceptance Criteria:**
- [ ] Un tableau par mois (12 tableaux)
- [ ] Chaque ligne de retraitement est justifiée
- [ ] Le total des retraitements est affiché

---

#### FR-202: Calcul du tableau de passage annuel
**Priority:** Must Have

L'outil produit une synthèse annuelle.

```
                        BRUT      NORMALISÉ    ÉCART
Charges mensuelles     897 K€      861 K€      -4%
Produits mensuels      955 K€      948 K€      -1%
Résultat annuel        694 K€      917 K€     +32%

DÉCOMPOSITION RETRAITEMENTS
IS redistribué                    +234 K€
Provisions créances net            -15 K€
Exceptionnel net                    +4 K€
ABT (neutre)                         0 K€
────────────────────────────────────────────
Total                             +223 K€
```

**Acceptance Criteria:**
- [ ] Run rate brut vs normalisé affiché
- [ ] Écart en % affiché
- [ ] Décomposition des retraitements ligne par ligne

---

#### FR-203: Règles de retraitement
**Priority:** Must Have

| Élément | Règle | Justification |
|---------|-------|---------------|
| IS (695) | Étaler sur 12 mois | One-shot non-opérationnel |
| Exceptionnel (67/77) | Exclure | Non récurrent par définition |
| Provisions (68x) | Net avec reprises (78x) | Lire le couple |
| ABT (488 qui soldent) | Neutraliser mensuel | Bruit budgétaire |
| Amortissements (681) | Ne pas toucher | Récurrents |
| Saisonnalité août | Ne pas toucher | Effet réel |

**Acceptance Criteria:**
- [ ] Chaque règle est appliquée automatiquement
- [ ] Les règles sont paramétrables (seuils)
- [ ] L'utilisateur peut overrider une règle

---

### Couche 3 : Alertes contextuelles

#### FR-301: Alertes utiles uniquement
**Priority:** Must Have

L'outil ne génère que des alertes contextualisées.

**Ce qu'on NE signale PAS:**
- Montant rond sur compte ABT (normal)
- Concentration décembre sur amortissements (normal)
- Creux août (congés = réel)

**Ce qu'on SIGNALE:**
- Nouvelle provision non budgétée
- Reprise sans dotation récente
- Compte nouveau en décembre
- Variation inhabituelle N vs N-1

**Acceptance Criteria:**
- [ ] Maximum 5-10 alertes par analyse
- [ ] Chaque alerte a un contexte (libellé, historique, impact)
- [ ] Chaque alerte suggère une action

---

#### FR-302: Format des alertes
**Priority:** Must Have

```
┌─────────────────────────────────────────────────────────────┐
│ ALERTE: Provision non budgétée                              │
├─────────────────────────────────────────────────────────────┤
│ Compte   : 6815 - Provisions pour risques                   │
│ Montant  : 15 000 €                                         │
│ Mois     : Décembre uniquement                              │
│ Libellé  : "Provision prud'hommes Dupont"                   │
│                                                             │
│ CONTEXTE:                                                   │
│ - Pas de compte 488 associé (non anticipé)                  │
│ - Première apparition de ce risque                          │
│                                                             │
│ QUESTION: Ce litige est-il ponctuel ou récurrent ?          │
└─────────────────────────────────────────────────────────────┘
```

**Acceptance Criteria:**
- [ ] Alerte en une seule vue
- [ ] Contexte métier fourni
- [ ] Question actionnable

### Couche 4 : IA (optionnelle)

#### FR-401: NLP extraction mots-clés
**Priority:** Could Have

L'IA extrait les mots-clés métier des libellés.

**Mots-clés cibles:** prud'hommes, CFE, CVAE, formation, CAC, AGEFIPH, IS, taxe foncière, etc.

**Acceptance Criteria:**
- [ ] Extraction sans configuration
- [ ] Rattachement au type de charge
- [ ] Aide à qualifier les ABT

---

#### FR-402: Détection changement de comportement
**Priority:** Could Have

L'IA détecte si un compte change de pattern entre N-1 et N.

**Acceptance Criteria:**
- [ ] Comparaison N vs N-1
- [ ] Alerte si changement significatif
- [ ] Suggestion de cause

## 3. Exigences non fonctionnelles

### NFR-201: Temps de lecture rapport
**Priority:** Must Have

Un DAF doit pouvoir lire et comprendre le rapport en **moins de 30 secondes**.

**Acceptance Criteria:**
- [ ] Synthèse sur 1 page/écran
- [ ] Chiffres clés en évidence
- [ ] Pas de jargon technique

---

### NFR-202: Fausses alertes
**Priority:** Must Have

Moins de **3 fausses alertes** par analyse.

**Acceptance Criteria:**
- [ ] Test sur 10 GL réels
- [ ] Comptage des alertes inutiles
- [ ] Ratio < 30%

---

### NFR-203: Tableau de passage toujours fourni
**Priority:** Must Have

**100%** des analyses produisent un tableau de passage.

**Acceptance Criteria:**
- [ ] Même si aucune anomalie, le tableau est généré
- [ ] Le tableau montre brut = normalisé si pas de retraitement

## 6. Flux utilisateur v2

```
1. IMPORT GL
   └── Charger fichier Excel

2. ANALYSE AUTOMATIQUE (< 2 min)
   └── Couche 1 : Lecture comptable
   └── Couche 2 : Calcul tableau de passage
   └── Couche 3 : Génération alertes

3. VALIDATION (optionnel)
   └── L'utilisateur valide/ajuste 3-5 alertes

4. RAPPORT
   └── Tableau de passage mensuel + annuel
   └── Run rate brut vs normalisé
   └── 3-5 alertes contextuelles
```

**Temps total : < 5 minutes** (vs workflow complexe en v1)
